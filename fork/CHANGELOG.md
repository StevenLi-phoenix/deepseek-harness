# Changelog

Fork-local changes on top of upstream DeepSeek Harness. Format: [Keep a Changelog](https://keepachangelog.com/). Upstream changes are not repeated here; see [`../packages/fork/UPSTREAM.md`](../packages/fork/UPSTREAM.md) for the upstream baseline.

## [Unreleased]

### Fixed
- The overview's Bilibili card is yellow (`svc_only`) when bili-svc answers but the DSH `bili` plugin is not mounted; it used to be green, which hid a plugin that failed to load (2026-11-01).
- Bus result notes no longer start with ✅, which read as the event's verdict while it only meant the turn finished; a batch of several events is titled by subject and count (`CI: owner/repo (4 events)`) instead of its first event, so a note about a failed run is not headed by another run's success (2026-11-01).
- The `ci` subscription tells the owner only what needs them: failures no code change fixes (secrets, quota, runners, outages), failed deployments or releases, and a default branch red twice in a row; branch and pull-request failures and successes answer NO_REPLY (2026-11-01).
- `bili_channel_note` asks `ctx.forkGuard` (purpose `bili-channel-note`, audience `channel`) after the local PII rules and refuses every note when the guard fails or is not mounted (2026-11-01); the persistent-Session idle archive of the bus is replaced by the shared sweep.
- A long-lived Session whose recorded model left the profile (renamed or removed) continues on the configured default route and logs the switch, instead of ending every turn with `UNKNOWN_MODEL` (2026-11-01; the WeChat chat Session failed from 10/31 10:00 after `deepseek-v4.1-flash` became `opencode-go/deepseek-v4.1-flash`).
- `fork-integrity` no longer reports "定时任务（定义）被改动了" whenever a daily or weekly task runs: `scheduledAt` of a repeating task is its next run time and is left out of the digest; it still counts for one-shot `at` tasks (2026-11-01).
- A final answer whose last line is exactly `NO_REPLY` is silent for `fork-event-bus` and owner-relay, so an explanation followed by `NO_REPLY` no longer reaches WeChat (2026-11-01).

### Changed
- The qq-digest transcript now tags each picture `[图片#m12ab]` and attaches the newest `digest.maxImages` (8, volatile, `0` = none) saved ones to the prompt as image parts when the route reads images (the same turn goes out as text when it refuses them); pictures reach the model only and are never stored (2026-11-01).
- The qq-digest transcript drops its noise (2026-11-01): a member's consecutive `[表情]`, `[动画表情]`, `[戳一戳]`, and `[合并转发]` messages are one line (`[表情]×3`) while every message still moves the digest cursor, and with `digest.aliasMembers` an @-mention shows the member's alias instead of the QQ number or name (`@某群友` when no member has that name; `@全体成员` stays).
- `fork-qq` is the recorder's client: `groupOverview()`, `recentMessages()`, `searchMessages()`, `evidenceOf()`, `groupChoices()`, and `loginStatus()` are async and fail with `RecorderUnavailable` while the recorder is down; `dataDir` is ignored (the recorder's `QQ_RECORDER_DATA_DIR`), `asr.enabled` and `send.enabled` fail the load, `sendGroupMessage` always refuses, and `recorder.{socket,tokenEnv,timeoutMs}` are new (schema defaults).
- `napcat.sh start` stores the OneBot token as the recorder's AMS secret (and still in `.env` for one release cycle) and restarts the recorder, not DSH.
- The QQ configuration warning in Settings no longer says a save reconnects QQ: only a changed `url` or `tokenEnv` does.
- `fork-wechat`'s time check defaults to 5 minutes (`timeGapMs` 300000, was 30 minutes) and uses `fork-time-gap`'s stamps and gap lengths; `fork-time-gap` leaves the owner's WeChat messages to it (`deferChannels: [wechat]`), so a chat message gets one notice (2026-11-01).
