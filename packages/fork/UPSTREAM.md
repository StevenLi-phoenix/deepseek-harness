# fork upstream ledger

This fork keeps upstream `packages/` untouched. Fork-local code lives in `packages/fork/*` (new packages) and `/fork` (deployment files). When an upstream package must change, copy it into `packages/fork/` under a new name that says what it changes (`@deepseek-ai/dsh-<function>`), record it here, and disable the upstream row in the profile patch instead of editing upstream files.

## Upgrade procedure

Before merging, read the new `docs/upgrade-guide/*` entries: a default changed upstream stays at its previous value through a row in `fork/bundles/event/cordis.patch.yml`, asserted in `packages/fork/bili/tests/bundle.spec.ts`.

1. `git remote get-url upstream || git remote add upstream https://github.com/deepseek-ai/deepseek-harness`, then `git fetch upstream --tags`.
2. For each copied package above: `git diff <upstream commit>..<new tag> -- <upstream path>` and port the relevant changes into the fork copy; update its row.
3. `git switch main && git merge <new upstream tag>`; resolve conflicts in the files listed under "Upstream files touched".
4. `pnpm install && pnpm run gen-tsconfig-paths && pnpm run build:artifacts`, then regenerate (`gen-cordis-catalog`, `gen-config-catalog`, `gen-client-catalog`, `gen-plugin-packages`, `verify-package-dependencies -- --fix`) and re-record changed README pairs (`verify-translation-pairing <README.md> --write`), then `pnpm exec vitest run packages/fork` and the fork gates in [`/fork/README.md`](../../fork/README.md).
5. Bump the version of every `packages/fork/*` manifest to the root version (the constraints gate requires it) and update the Baseline table.
